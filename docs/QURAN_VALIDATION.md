# نظام التحقق من القرآن

أهم جزء في المشروع هو سلامة نص القرآن. لذلك توجد طبقتان إلزاميتان قبل أي بناء Release:

```bash
npm run data:build
npm run validate:quran
```

## ما الذي يتحقق منه `validate-quran`؟

السكريبت: `scripts/validate-quran.mjs`

يتحقق من الآتي:

1. ملف المصدر UTF-8 ثابت ولا يحتوي على محارف Replacement.
2. SHA-256 لملف المصدر يساوي القيمة المحفوظة في `data/sources/quran/quran-json-3.1.2-quran.sha256`.
3. وجود 114 سورة بالضبط.
4. ترتيب السور: `surah.id` يجب أن يساوي الموضع `1..114`.
5. عدد الآيات لكل سورة حسب جدول معروف لمجموع 6236 آية.
6. أرقام الآيات داخل كل سورة تبدأ من 1 وتنتهي بعدد آيات السورة بلا فجوات.
7. عدم وجود سجل آية مكرر بنفس المفتاح `surahId:ayahNumber`.
8. عدم خلط آيات السور: كل آية في البيانات المولدة تحمل `surahId` و`surahName` المطابقين للأصل.
9. النص في `src/data/quran/quran.generated.json` يطابق النص في المصدر حرفيًا لكل آية.
10. عدد الآيات الكلي 6236.
11. `sourceSha256` داخل البيانات المولدة يطابق Hash المصدر.

> ملاحظة: قد تتكرر بعض نصوص الآيات شرعًا داخل القرآن، لذلك لا يُعد تكرر النص نفسه خطأ. الممنوع هو تكرر سجل بنفس الموضع أو فقدان موضع.

## متى يفشل البناء؟

`npm run build` يشغّل:

1. `data:build`
2. `validate:quran`
3. `validate:data`
4. `lint`
5. `vite build`

أي فشل في التحقق من القرآن يوقف البناء فورًا.

## سياسة تعديل بيانات القرآن

- لا يُعدّل ملف القرآن يدويًا.
- لا تُصحح آية يدويًا داخل الكود.
- أي تغيير للمصدر يتطلب:
  1. توثيق المصدر الجديد.
  2. حفظ الملف الأصلي في `data/sources/quran/`.
  3. تحديث Hash المصدر.
  4. تشغيل `validate:quran`.
  5. مراجعة بشرية متخصصة قبل Release.
